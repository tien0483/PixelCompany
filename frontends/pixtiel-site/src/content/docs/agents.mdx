# Agent CLIs & Skills

PIXTiel is not tied to one vendor. The harness is a **per-card setting**, so switching providers
is a dropdown rather than a migration, and the parts that should not change per vendor — worktree
isolation, checkpointing, seat accounting, token compression — are the platform's job.

---

## Launchable harnesses

These are the agents a card can start today:

| Harness | Card label | Auth | Notes |
|---|---|---|---|
| **Claude Code** | `Claude Code` | Anthropic OAuth (per-seat) | Default. Supports a separate subagent seat and per-card MCP allowlists. |
| **Cursor Agent** | `Cursor Agent` | Cursor account or `CURSOR_API_KEY` | Pin a Cursor seat on the card instead of switching accounts in the IDE. |
| **Cline** | `Cline` | API key (multi-provider) | Runs in-process through the SDK; needs an API-key seat to appear in the picker. |
| **Antigravity CLI** | `Antigravity CLI` | Google account (per-seat) | Headless print mode with per-task hooks. |
| **Custom Agent** | `Custom Agent (dsh)` | DeepSeek Harness on PATH | Bring your own harness; the card supplies the prompt and worktree. |

The catalog also carries **OpenAI Codex**, **Factory Droid**, **Kiro** and **OpenCode** entries.
They are not launchable yet — they appear in the model, not the launcher — so treat them as
planned rather than shipped.

## What a card pins before launch

Every card is configured independently, and none of it is a global setting:

- **Harness and model** — pick the agent and the exact model id it should run.
- **Reasoning effort** — where the harness supports it (`low` … `max`).
- **Primary seat** — which account this card's main session bills.
- **Subagent seat** — optional; the account this card's *subagents* bill instead. See
  [Multi-Account Seats](/docs/seats).
- **Base branch** — resolved and locked at worktree creation, so the diff stays honest even
  after `main` advances.
- **Permission mode** — start in plan mode to make the agent propose before it edits. The mode
  survives automatic restarts.
- **Skills, MCP servers and launch tags** — which shelves and tool servers are mounted for this
  card only.
- **Allowed tools** — restrict what the session may run.

MCP secrets are not pasted into the card. Store them once in the vault and PIXTiel injects them
into the launch environment of whichever harness the card uses.

## The token stack

Installed with the `agent-stack` feature, inside the repository — nothing global, nothing to
uninstall later. Every task agent gets these on PATH:

| Tool | What it does |
|---|---|
| **rtk** | A CLI proxy that compresses bulky shell output — `rtk git status`, `rtk tsc`, `rtk lint`, `rtk test`. Only helps for shell commands; file reads go through the agent's own tools. `rtk gain` reports what it saved. |
| **Caveman** | Compresses prose: drops filler and preamble while keeping technical substance, code blocks and exact error text intact. |
| **Understand-Anything** | Builds a knowledge graph of the repository, then answers architecture questions ("what calls this", "where does that get set") from the graph instead of a dozen file reads. Also powers the Understand dashboard and review blast radius. |
| **Headroom** | A proxy that rewrites context on the way upstream. Worth watching your cache-hit rate after enabling it — see the note below. |
| **Ponytail** | A review lens that hunts over-engineering: what to delete, what the standard library already does. |
| **Switchboard** | The control panel and router on `127.0.0.1:8000`, with a per-tool toggle file. |
| **CCR / DevTools** | Optional routers, off by default. |

<div class="not-prose my-6 p-4 rounded-xl border border-[#30363D] bg-[#24292E]/60 text-sm">
	<strong class="text-[#E6EDF3]">A caveat worth knowing.</strong> Sessions on a warm repository run
	a very high prompt-cache hit rate. Anything that rewrites context can break the cache prefix,
	which turns a cheap cache read into a full write. Enable Headroom, then watch your usage — and
	remember <code>pnpm start -- --no-proxy-env</code> is the lever that takes agent traffic back off
	the chain.
</div>

## Skills, agents and commands

Beyond the stack, PIXTiel ships a catalog you enable per project from the Manager shelves:

- **29 skills** — reusable procedures an agent invokes by name (planning, QA, recovery,
  design passes, subagent spawning, and so on).
- **10 agent definitions** — pre-authored `.claude/agents` personas.
- **30 slash commands** and **2 rule files**.

Toggling one on copies it into the project so the agent discovers it without prompting. Skills
live under your repository:

```bash
.claude/skills/     # Claude Code discovers these
.agent/skills/      # shared shelf, symlinked per task worktree
```

Author your own with the **Agent studio** (the `agent-creation` feature) — a canvas with
credential-free nodes wired to the seats you already manage.

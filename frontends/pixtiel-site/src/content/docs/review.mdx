# Merge Requests & Code Review

Reviewing AI-generated code should not happen in a chat transcript. PIXTiel brings the full GitLab/GitHub merge request review workflow directly into the board, transforming review into an active quality gate with automated feedback loops.

---

## Why Review as a Diff?

In chat interfaces, evaluating code changes requires scrolling through walls of markdown explanations and speculative file summaries. 

In PIXTiel:
- The **Review Tab** computes a real whole-branch git diff against the card's locked base branch.
- You review file-by-file with syntax highlighting, hunk folding, and change stats.
- Comments left on specific lines are routed directly back into the agent's worktree as scoped revision tasks.

```
┌────────────────────────────────────────────────────────────────────────┐
│ Review: [Branch: feat/vault-store] ──► [Base: main]   (+240 / -18)     │
├────────────────────────────────────────────────────────────────────────┤
│ ▼ src/security/vault-store.ts                                          │
│   42:  export async function writeSecret(key: string, val: string) {   │
│   43:    const cipher = crypto.createCipheriv('aes-256-gcm', key, iv); │
│ + 44:    // User comment: "Ensure IV is generated with randomBytes"    │
│ + 45:    // Agent Action: Refactoring hunk to use crypto.randomBytes   │
└────────────────────────────────────────────────────────────────────────┘
```

## GitLab & GitHub Connect

PIXTiel integrates directly with your remote Git forge:

1. **GitLab**: connect over OAuth from the Review tab, or store a Personal Access Token in the
   vault. One GitLab identity is shared across seats.
2. **GitHub**: store a PAT in the vault; PIXTiel plumbs it to the session as `GH_TOKEN`, and
   picks up an authenticated `gh` CLI when one is present.
3. **Vault security**: tokens live in the local credential store — directories `0700`, files
   `0600`. API responses return key *names* and a masked last-4, never values, and nothing is
   written to your global agent settings.
4. **Remote sync**: push the card's branch and open the merge request without leaving the board.

## Inline Line Comments & Agent Revision Loop

When you find an issue in a diff:

1. Click any line number in the diff viewer.
2. Type your review comment (e.g., *"Handle edge case when token is expired"*).
3. Click **Send to Agent**.
4. PIXTiel dispatches a focused revision instruction directly to the agent in that worktree. The agent reads the exact hunk, applies the fix, runs test suites, and updates the branch diff.

## Blast-Radius & Knowledge Graph Impact

Before approving a merge, evaluate the structural impact on the rest of your codebase:

- **Understand knowledge graph**: when the project has a graph, PIXTiel walks it — modules,
  exported symbols and edge direction — rather than guessing from file paths.
- **Blast radius**: the panel lists which downstream files depend on what the diff touched.
  Containment is not impact and edges have a direction, so a file that merely *contains* a
  changed symbol is not reported as affected by it.
- **No graph, no guessing**: with no graph present the panel says so instead of showing an empty
  result that reads like "nothing is affected". Build one from the **Understand** tab — it reads
  the whole repository, so it is never built automatically.

Deciding what to re-run is still yours: PIXTiel surfaces the affected surface, it does not gate
the merge on a test suite it chose for you.

## Landing the Card

Once the diff meets quality standards:

- **Merge to Base**: Merges the card's worktree branch into your local `main` branch with clean git history.
- **Push to Remote**: Pushes the branch upstream to trigger CI/CD pipelines.
- **Archive Worktree**: Automatically cleans up the ephemeral git worktree while preserving turn checkpoints and audit logs in `refs/kanban/checkpoints/`.

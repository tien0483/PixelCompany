Products

One workspace, seven surfaces — two of them ship on their own.

PIXTiel is one local install. The board is the core; everything else is a feature you tick on during setup and can add later. The installer also builds the plan editor and Review as self-contained packages you can hand to someone who does not want the board. Nothing phones home, and every service binds to loopback.

Core · always installed

The board

Every task is a card, every card is a git worktree.

Cards move Backlog → Planning → In Progress → Review → Done. Moving a card into progress cuts a git worktree on its own branch and launches the agent you pinned to it, so parallel agents never touch each other's files. Live xterm output streams into the card, and turn checkpoints land in refs/kanban/checkpoints so a purged worktree is recoverable.

  • Per-card agent, model, reasoning effort, base branch and skill shelf
  • Chain cards with explicit dependencies; followers inherit the merged base
  • Backlog autorun with a configurable parallel-task ceiling

Feature · plan-editor

Plan editor

Plans are documents you can diff, not chat scrollback.

Write the plan before the code. Plans are versioned HTML documents with templates, an AI refine pass you review as a diff, and per-agent sub-plan splitting for work that fans out. A card can start in plan mode so the agent proposes before it edits.

  • Template shelf and import from an existing folder of plans
  • Refine with an agent, then accept or reject the diff
  • Split one plan into per-card sub-plans for a fan-out

Feature · review

Review

A real branch diff, with comments that route back to the agent.

Review computes a whole-branch diff against the card's locked base ref — not a summary of what the agent claims it did. Leave line comments and send them back as scoped revision work. Connect GitLab over OAuth or store a PAT in the vault to push branches and open merge requests without leaving the board.

  • Whole-branch diff against the immutable base ref
  • Line comments dispatched to the agent in that worktree
  • Blast radius from the Understand knowledge graph when one exists

Feature · agent-creation

Agent studio

Author an agent on a canvas instead of in a config file.

A forked Flowise canvas, embedded in the board, with a curated node palette and three credential-free LLM nodes that bill against the seats you already manage. Runs on loopback only — the canvas executes code by design, so it is never exposed to the network.

  • Claude, Antigravity and Cursor nodes wired to your seats — no API keys pasted into the canvas
  • Curated palette; a fail-open allowlist keeps saved flows working
  • Loopback bind plus scoped embed origins are the whole boundary

Bundled sidecar

Learning room

A classroom for the codebase, next to the board.

OpenMAIC embedded as a center-pane view, so course-style material and multi-agent explanations sit beside the work instead of in another tab. Its LLM calls use the seats PIXTiel already holds.

  • Embedded, not linked — same window, same session
  • Speech and TTS routed through your Manager API seat
  • Degrades to an Open-in-tab button if the build refuses framing

Core · Manager

Seats & Manager

Rate limits become a scheduling problem.

Manager tracks every account you own — OAuth sessions and API keys — with live 5-hour and 7-day usage windows. Cards pin a primary seat, and optionally a separate seat that only their subagents bill, so orchestration overhead stops eating the quota you want for code.

  • Usage-aware parking and resume with --continue, or failover to a standby seat
  • Same-seat login recovery before any cross-seat swap
  • Subagent seats: subagent traffic diverted per card, parent keeps its own OAuth

Feature · agent-stack

Agent stack

Token cost is a first-class feature, not an afterthought.

A seven-tool stack installed inside the repo, never globally: rtk compresses bulky shell output, Caveman compresses prose, Understand-Anything answers architecture questions from a graph instead of a dozen file reads, and Headroom rewrites context on the way upstream. Every task agent gets them on PATH.

  • rtk — token-compressing CLI proxy for git/tsc/lint/test output
  • Understand-Anything — knowledge graph, dashboard and diff impact
  • Switchboard on :8000 with a per-toggle control panel

Standalone package

Plan editor standalone

The plan editor as a folder you can hand to someone.

The same markdown-to-HTML plan editor, built as a self-contained package: write the plan, refine it with an agent, pick a papp template, generate the page. No board, Office, git view or accounts UI. It needs Node and a locally logged-in Claude Code CLI, and no credential of any kind is bundled. Plans land in the same runtime data folder the full app uses, so nothing is lost if you install PIXTiel later.

  • Ships as a folder or a zip — start.sh on macOS/Linux, start.bat on Windows
  • ~50 MB built --slim; a one-time build.sh installs the sidecar's deps on the target
  • Versioned plans with undo, redo and history, backed by git objects
feature: plan-editor-standalone127.0.0.1:4173

Standalone package

Review standalone

Merge-request review without the rest of the workspace.

Read a GitLab merge request side by side, check it against your team's own extracted rules, draft inline notes locally, and publish them in one action. Authorize GitLab once on the loopback callback; the token is stored in your home runtime data folder at mode 0600. Drafts persist per merge request, so closing the tab discards nothing.

  • No sidecar, so every build is already slim — Node 20 and go
  • Rules extracted from your own guideline documents, each citation traceable to its heading
  • Runs on 4183, clear of the plan editor's 4173, so both packages coexist
